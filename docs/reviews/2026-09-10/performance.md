# Klexi performance review — 2026-09-10 (원문, code-verified)

**1. P1 — Cold start blocked on RevenueCat network call.** `lib/main.dart:43` awaits `PurchaseService.initialize()` before `runApp`; `lib/core/services/purchase_service.dart:48` awaits `Purchases.getCustomerInfo()`, which hits the network on first launch or when the SDK cache is stale (>5 min backgrounded). On poor network the splash stays blank for the SDK timeout. Also `Purchases.configure` (line 38) is outside the try/catch — a throw there means `runApp` never runs. The listener at line 42 already updates `premiumProvider`, so the awaited fetch is redundant. Fix: `runApp` first, then `unawaited(PurchaseService.instance.initialize())` wrapped in try/catch. Confidence: high.

**2. P1 — Word Network ticker rebuilds the entire screen every frame.** `word_network_screen.dart:98` starts a Ticker whose callback calls `setState` (line 193) 60×/s, rebuilding the whole Scaffold: `_FilterBar` (up to 102 category chips, each an `AnimatedContainer`, lines 904-916), `_StatsChip`, `_WordPanel`, and `_visibleNodes` list copies 2–3× per build (lines 220, 412, 459, 470). `onPointerMove` (line 397) adds a second `setState` per frame during drag. `shouldRepaint => true` (840). Fix: keep node positions in a `ChangeNotifier` passed as `CustomPainter(repaint:)`; never `setState` from the tick. Confidence: high.

**3. P1 — Painter allocates a TextPainter and lays out Korean text per node per frame.** Lines 793-804 and 809-816 create + `layout()` a `TextPainter` for every on-screen node each frame once `scale > 0.2` (~0.1–0.3 ms each for CJK shaping): 150–300 nodes ⇒ 15–60 ms/frame, well over the 16 ms budget. Four to five `Paint()` objects are also allocated per node (760-784), `posMap` is rebuilt every frame (666-669), and `_hovered` does a linear scan (626). Fix: cache `TextPainter` per `(word.id, fontSize, weight)` and only change the paint offset; hoist Paints to fields. Confidence: high.

**4. P1 — Proximity-edge loop draws thousands of lines per frame.** Lines 675-695: for each node, up to 39 following same-category nodes are tested with a 300 *screen*-px threshold. At the default fit scale (~0.15 on a 390-px phone, the whole 2,200-px disc is ~330 px) almost every pair qualifies: ~150×39 ≈ 5.8k (300 nodes: ≈ 11.7k) `drawLine` calls with a per-call color change, at 60 fps. Fix: precompute the edge list once per node set (positions only wobble ±5 px, line 198), threshold in graph space, and batch by color via `drawPoints(PointMode.lines)`. Confidence: high.

**5. P2 — TTS MP3 cache grows without bound; hash-key collisions.** `tts_service_mobile.dart:28-34` writes every clip to `tmp/tts_cache` with no size cap or eviction. Worst case for a premium user: 7,200 words + examples × 2 speeds × 2 engines ≈ 28k files × ~20 KB ≈ 500 MB (OS may purge temp, but not reliably). Key is `text.hashCode` (line 17) — collisions play the wrong audio. `getTemporaryDirectory()` platform call happens twice per `speak` (lines 9-14). All file IO is async — no sync IO found. Fix: cache dir path once; LRU-trim by mtime to ~50 MB on init; key by SHA-1 of text. Confidence: high.

**6. P2 — Daily session recomputed on every screen open.** `daily_session_service.dart:107-181` rebuilds a `StudyRecord` map from every Hive key, then scans all 7,200 words calling `DateTime.now()` per record (line 51). Invoked via `getTodayWordIds` from `daily_session_screen.dart:34`, `pronunciation_screen.dart:60`, `sentence_card_screen.dart:87`, quiz, review — ~2–5 ms each on the main isolate. Home `_load` (home_screen.dart:37-41) makes three separate full box scans (service lines 227, 276, 301). Fix: memoize the session per `AppConfig.daySeed`; compute streak/total/today in one pass. Confidence: high.

**7. P2 — Vocabulary is compiled in (good) but not const.** `Word extends HiveObject` (word.dart:6), so `level*_part*.dart` lists are `final`, not `const`: first touch of `WordRepository._all` (word_repository.dart:20-39) allocates 7,200 `Word`+`HiveObject` instances plus a spread copy (~1 MB, ~5–15 ms) on the first home build via `home_screen.dart:426`. No `Box<Word>` is ever opened (only `Box<Map>`), so `HiveObject` and `WordAdapter` are unnecessary. Fix: drop `HiveObject`, make the constructor `const`, make lists `const` → zero runtime allocation. Confidence: high.

**8. P2 — Fonts fetched at runtime; declared Korean font does not exist.** `pubspec.yaml:89` states fonts load via `google_fonts` at runtime; `app_theme.dart:132` uses `GoogleFonts.dmSansTextTheme` → network download on first launch, fallback-then-swap flicker, fallback forever if offline. `fontFamily: 'NotoSansKR'` (word_network 797, home_screen 493, `app_typography.dart:7`) is never declared in a `fonts:` section, so it silently falls back to the system font; the bundled Pretendard TTFs in `assets/fonts/` are likewise undeclared and unused. Fix: declare fonts in pubspec, bundle DM Sans, set `GoogleFonts.config.allowRuntimeFetching = false`. Confidence: high.

**9. P2 — Avatar images have no disk cache or decode limit.** `home_screen.dart:92` `NetworkImage(user!.photoUrl!)` and `settings_screen.dart:322` `Image.network` re-download on every cold start; `cached_network_image` is in pubspec but unused anywhere in `lib/`. Fix: `CachedNetworkImageProvider` + `cacheWidth`. Confidence: high.

**10. P2 — Dead/unused plumbing.** `Word.relatedIds` is never populated in any vocab file (0 hits), so `_WordPanel`'s "Related" section (line 1001) can never render while the painter uses `relatedMap` — and `relatedWordsMap` covers only 8 keys/160 entries. `flutter_animate` is declared but never used (no jank source there). Confidence: high.

**Checked and OK:** all `Ticker`/`AnimationController`/`TabController`s are disposed (word_network 104-108, sentence_card 42-45, pronunciation 48-52, review 35-38); no `Timer.periodic`; the three non-builder `ListView(`s hold 7 chips each; `getWordsByLevel`/`categories`/`buildRelatedIdsMap` are cached; Hive box opened once (`DailySessionService.init`, idempotent).
